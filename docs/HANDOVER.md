## 1. Product in one page

**Sportzicon** — "Where talent gets seen. Where the sports ecosystem gets built." A cricket-first sports network that connects six roles:

| Role (DB value) | What they do in the app |
|---|---|
| Athlete (`athlete`) | Verified "passport" profile, post reels/photos/scorecards, apply to trials and jobs, message scouts/academies |
| Coach / Academy (`coach`) | Organization account: post trials/jobs, review applicants, verify athletes' stats, rate skills, roster |
| Scout / Selector (`scout`) | Search verified talent, shortlist, message |
| Club / Franchise (`club`) | Organization account: recruit players/staff, enter tournaments |
| Organizer / Association (`organizer`) | Organization account: host tournaments, official trials |
| Official Scorer (`scorer`) | Ball-by-ball live scoring; completing a match writes verified stats to linked athletes |

### Decisions agreed with the product owner
- **Platform:** native mobile app (React Native / **Expo**), iOS + Android. A web build exists and is deployed for easy sharing. Layout is phone-first; on web it is capped at 480 px and centered.
- **Scope v1:** social & profile, recruitment & search, live scoring, organization dashboards — all built.
- **Backend:** **Supabase** (Postgres + Auth + Storage + Realtime).
- **Sign-in:** email + password, Google, Apple. (Google/Apple are coded but **not yet configured** in Supabase — see §10.)
- **Roles:** one role per account, chosen at sign-up. Academies/clubs/organizers are **organization accounts**; the sign-up user becomes the org admin.
- **Verification:** stats from a match scored live on Sportzicon are verified automatically when the scorer completes the match; self-reported stats are confirmed by the athlete's academy/club. No admin team.
- **Sports:** cricket-first; data model has a `sport` column so other sports can be added later.
- **Design:** original Sportzicon palette + logos (see §6). Approved designs live on a design canvas: https://claude.ai/artifact/97WxbKFCakdnKdxdxrDerz (13 phone screens).
- **Dropped from the old prototype:** the UI/UX audit suite and the demo role switcher.

### Key patterns
- **Auth guard:** `_layout.tsx` uses `Stack.Protected` — signed-out → `sign-in`/`sign-up`/`forgot-password`; signed-in but not onboarded → `onboarding`; onboarded → `(app)`. **Every signed-in screen must live under `(app)/`**, otherwise Expo Router treats it as public and signed-out users can land on it.
- **Role-based tabs:** `tabsForRole()` in `(app)/(tabs)/_layout.tsx` — athletes/scouts get Opportunities, org roles get Manage, scorers get Matches.
- **Server state:** components never call Supabase directly except small one-offs; use hooks in `lib/api`. Mutations patch caches optimistically (endorse, save, shortlist, messages, scoring).
- **Realtime:** messages (per thread), match balls/state (per match), notifications (once per user, in `(app)/_layout`). Channel names for per-screen subscriptions include a random suffix so two mounts never share a channel.
- **Scoring engine:** `lib/cricket.ts` derives everything (score, overs, batters/bowlers, strike rotation, over end, all-out, target, result) from the `balls` table. **Undo = delete the last ball.** The scorer console writes the "next striker/non-striker/bowler" back to `matches` after each ball.
- **Dialogs:** `lib/dialog.ts` → native Alert/ActionSheet on iOS/Android, `window.confirm`/in-app sheet on web.
- **Navigation to dynamic routes:** `go(`/profile/${id}`)` from `lib/nav.ts`.

## 5. Database (Supabase)

Migrations in `app/supabase/migrations/` (run in order in the Supabase SQL editor, or `supabase db push`):
1. `20261119000000_init.sql` — everything below.
2. `20261119010000_fix_org_members_policy.sql` — fixes an RLS self-reference ("infinite recursion") on `org_members` via `is_org_admin()`.

Optional `app/supabase/seed.sql` — 4 sample organizations + 5 open opportunities.

**Both migrations and the seed are already applied** to the live project.

### Tables
`organizations`, `profiles` (1:1 with `auth.users`; role, passport_code, skill_ratings jsonb, org_id, onboarded), `org_members`, `posts`, `post_endorsements`, `post_comments`, `saved_posts`, `opportunities`, `applications`, `shortlists`, `saved_opportunities`, `conversations`, `conversation_members`, `messages`, `matches`, `match_players`, `balls`, `performances`, `notifications`. View: `post_stats`.

### Functions (RPC) & triggers
- `handle_new_user` (trigger on `auth.users`): creates the profile from sign-up metadata (`full_name`, `role`).
- `create_organization(kind, name, city)`: creates org, makes caller admin, links profile.
- `start_conversation(other)`: find-or-create 1:1 thread.
- `review_performance(id, approve)`: academy staff verify/reject an athlete's self-reported stats.
- `rate_skills(athlete, ratings)`: academy staff set coach ratings.
- `complete_match(match, result)`: scorer locks a match and inserts **verified** performances for linked players.
- Notification triggers: new application (→ org staff), application status change (→ applicant), new message, endorsement, shortlist, verification.
- Helpers: `is_org_staff(org)`, `is_org_admin(org)`, `is_conversation_member(conv)` (security definer, avoid RLS recursion).

### Security (RLS) summary
Directory data (profiles, orgs, posts, opportunities, matches) readable by any signed-in user. Writes are owner-only; org data only by org staff; applications visible to applicant + org staff; messages only to members; athletes cannot mark their own stats verified; balls only by the match's scorer while live.

### Storage
- `media` (public): post photos/videos at `<userId>/<timestamp>-<name>`.
- `avatars` (public): profile photos.
- `documents` (private): application attachments; readable by the uploader and staff of the org they applied to (signed URLs).
Upload policy: users can only write inside their own `<userId>/` folder. Deleting a post also deletes its media file.

### Auth settings currently on the live project
- Email provider on, **"Confirm email" OFF** (turned off for testing — turn back on before launch).
- Google/Apple providers **not enabled yet**.

## 9. Gotchas we hit (read before changing these areas)

1. **`Alert.alert` is a no-op on web** → use `notify/confirm/chooseAction` from `lib/dialog.ts`.
2. **`fetch(fileUri).arrayBuffer()` returns ~14 bytes on Android** → uploads go through `lib/read-bytes.native.ts` (expo-file-system `File`). Web uses fetch on the blob URL.
3. **Expo Router protected routes:** routes outside `Stack.Protected` are public; keep signed-in screens in `(app)/`. Duplicate `index` routes in two groups conflict.
4. **Typed routes reject template-string hrefs** for dynamic routes → use `go()` from `lib/nav.ts`.
5. **SDK 58 bottom tabs API:** custom tab bars receive `navigateToTab(routeKey)` (not `navigation`); import the type from `expo-router/tabs`.
6. **Supabase realtime:** creating a channel with a name already subscribed throws "cannot add postgres_changes callbacks after subscribe()". One notifications channel app-wide; per-screen channels get a random suffix.
7. **RLS recursion:** a policy on a table that queries the same table recurses → use `security definer` helper functions.
8. **PostgREST embeds:** tables with multiple FKs to `profiles` need FK hints, e.g. `profiles!posts_author_id_fkey(...)`, `organizations!profiles_org_id_fkey(...)`.
9. **jsonb doesn't keep key order** → skill ratings are displayed in a fixed order from `skillsFor()`.
10. **React Native Web layout:** `flex: 0` collapses items to 0 width; give fixed `width`. Video on web needs `width/height: 100%` inside an `overflow: hidden` box.
11. **Dates:** `parseDob` rejects future dates (birthdays, played matches); use `parseDate` for deadlines/events.
12. **Cricket results** count wickets in hand out of 10 (`max(10, squad-1) - wickets`) even when fewer players were entered.
13. **`eas init` may add `RECORD_AUDIO`** via the image picker plugin → it's blocked in `app.json` (`blockedPermissions`) and `microphonePermission: false`.

## 10. Deployment

- **Web:** `npx expo export --platform web && npx eas-cli@latest deploy --prod` → https://sportzicon.expo.app (new domains take ~5 minutes to activate the first time).
- **Android APK for testers:** `npx eas-cli@latest build -p android --profile preview` → install link/QR on expo.dev. Signing keystore was generated by EAS and is stored on Expo's servers (don't regenerate it, or updates won't install over old versions).
- **Store builds:** `--profile production` then `eas submit` (needs Google Play $25 one-time / Apple Developer $99/yr).
- Build-time env vars come from `eas.json → build.base.env`.
